# ICE — Instruction, Context, Expectation

> Fórmula **ágil e simplificada** do guia de prompts essenciais para UX Designers. Ideal para estruturar instruções rápidas do dia a dia.

| | |
|---|---|
| **Categoria** | UX/UI · Uso diário / rápido |
| **Melhor para** | Tarefas pontuais e de alta frequência, quando você não quer montar um briefing longo |
| **Nível** | Iniciante |

---

## Quando usar

Use o ICE quando você precisa de **velocidade** e a tarefa não exige toda a estrutura de um [CARE](CARE.md) ou [C-C-E-R-A](C-C-E-R-A.md). É o "framework de bolso": três campos, resposta rápida.

## Anatomia

| Componente | O que é | Pergunta-guia |
|---|---|---|
| **I — Instruction** (Instrução) | O papel da IA e sua ação principal. | Quem ela é e o que faz? |
| **C — Context** (Contexto) | Background de pesquisa, dados do usuário ou metas do projeto. | Que informação ela precisa saber? |
| **E — Expectation** (Expectativa) | Regras de saída e formato de entrega. | Como eu quero receber? |

---

## Template (copie e preencha)

```text
INSTRUCTION: Aja como [papel] e [ação principal].
CONTEXT: [Background relevante — usuário, dados, meta.]
EXPECTATION: Entregue [formato + regras — ex.: 5 bullets, tom informal, máx. 2 linhas cada].
```

## Exemplo preenchido — Ideação de microcopy

```text
INSTRUCTION: Aja como UX Writer e crie mensagens para um estado de erro de conexão.
CONTEXT: App de delivery; o erro aparece quando o pagamento falha por rede instável.
O usuário está com fome e ansioso para finalizar o pedido.
EXPECTATION: 5 variações de mensagem, tom acolhedor e sem culpar o usuário,
cada uma com título (máx. 4 palavras) + descrição (máx. 12 palavras) + rótulo de botão.
```

---

## Dicas rápidas

- Ótimo para **iterar rápido**: gere, ajuste o Context e rode de novo.
- Se a resposta vier genérica, o campo fraco quase sempre é o **Context** — dê um dado concreto.
- Quando a tarefa crescer (pesquisa, tela para dev), suba para o [CARE](CARE.md) ou [RTCF](RTCF.md).
